# Phase 2 HTML Artifacts

Two pages, generated by `scripts/podcast_build.py` from a normalized package JSON. Both pages share `assets/podcast-html/artifact.css` and `artifact.js` (inlined at render time so each HTML file is self-contained).

Companion docs:
- [design-principles.md](design-principles.md) — durable rules that govern visual decisions.
- [notes-schema.md](notes-schema.md) — data contract the renderer reads.

## The two pages

| File | Job | Audience |
|---|---|---|
| `final/podcast-at-a-glance.html` | Investor briefing — replaces the podcast for a reader who needs to scan-and-walk-away with the substance. | The reader who isn't going to listen. |
| `final/annotated-transcript.html` | Long-form readable transcript with chapter navigation. | The reader who wants the verbatim conversation. |

Both pages embed `episode.package.json` in a `<script type="application/json">` tag. The briefing payload is **slimmed** — `turns` and `keywords` are stripped before embedding, since the briefing doesn't need them. The transcript embeds the full package.

## Durable navigation: folder tabs

Every page has the same topbar:

```
[Brand: title + show#]  [Briefing] [Transcript] [Listen ↗] [Show notes ↗] [Official transcript ↗]
```

Behavior:
- Briefing / Transcript are internal — same-window navigation.
- Listen / Show notes / Official transcript are external — `target="_blank" rel="noopener noreferrer"`.
- The active page's tab has paper-color fill and no line below it (folder opens to content).
- Inactive tabs sit behind with paper-tint fill and the topbar's bottom border visible.
- Listen is sourced from `episode.episode_url`. Show notes / Official transcript are matched from `links` by label regex (case-insensitive `show notes`, `official transcript`).

The folder-tab pattern is **not negotiable** per [design-principles.md](design-principles.md). Don't replace it with a hamburger menu or a generic nav bar without checking with the user.

## Briefing: three-column studio

```
┌──────────────────────────┬────────────────────────────┬─────────────────────────┐
│ EPISODE HERO             │ THE THESIS                 │ COMPANIES (entity card) │
│   kicker + multi-color   │   italic serif blockquote  │   • OpenAI ↗            │
│   title + meta + summary │                            │   • Stripe              │
│                          │ WHAT TO TAKE AWAY          │   ...                   │
│ ABOUT THE GUEST          │   01. ...                  │ ORGANIZATIONS           │
│   bio + canonical link   │   02. ...                  │ CONCEPTS & TECH         │
│                          │   (stacked single column)  │ BOOKS MENTIONED         │
│                          │                            │ HEALTH & LONGEVITY      │
│                          │ NOTABLE CLAIMS             │ READ NEXT               │
│                          │   [headline + body + ev]   │   list of source links  │
└──────────────────────────┴────────────────────────────┴─────────────────────────┘
```

### Left column: episode + guest

- **Episode hero card** — multi-color title (each comma-separated phrase gets a different color), short description, byline meta line. Position: sticky, top-aligned with topbar.
- **About the guest card** — single-line bio pulled from the first `person`-category term whose name appears in `episode.guests`. Includes a canonical link if found in `links`.

### Center column: thesis + takeaways + claims

- **The thesis** — italic serif blockquote of `bottom_line`. No left-handle bar.
- **What to take away** — stacked numbered list of `takeaways`, monospace numerals + serif body. Single column (never a grid of tiles).
- **Notable claims** — one card per claim. Each card has a sub-headline (`topic`), a 1–3 sentence body (`claim`) explaining the mechanism, and a small `Evidence:` line below. Topics must be position-establishing headlines per [design-principles.md](design-principles.md), not category labels.

### Right column: entity inspector + read next

Groups terms from `verification.terminology` by `category`, in this priority order:
1. People (filtered to exclude host + guest, who already appear in the hero/about-the-guest cards)
2. Companies
3. Organizations
4. Concepts & Tech
5. Books mentioned
6. Health & longevity (Tim Ferriss legacy bucket — generic categories fall back to alphabetical)

Each entity row:
```
● <name> [↗ link if t.url present]
  <one-line note>
```

Followed by **Read next** with up to 6 entries from `links`.

### Browser interactions

- Clicking an entity name with a URL opens that URL in a new window.
- Internal anchors (briefing → transcript via Read next or colophon) stay in the same window.

## Transcript: rail + prose

```
┌───────────────────┬──────────────────────────────────────────┬─────────┐
│ Search transcript │ Title + bottom line                      │  (gap)  │
│ CHAPTERS          │ ──────────────                           │         │
│   00:00 Start...  │ 00:00:00 Start and framing               │         │
│   02:21 AI IPO    │ Opening and sponsor material...          │         │
│   ...  (sticky    │                                          │         │
│   scroll-spy)     │ TIM FERRISS  Elad, nice to see you. ...  │         │
│                   │ ELAD GIL  Great to see you, as always.   │         │
│                   │ ...                                      │         │
└───────────────────┴──────────────────────────────────────────┴─────────┘
```

### Left rail (sticky)

- **Search transcript** input at the top. As the reader types, occurrences are marked in-place with `<mark>` and the page scrolls to the first match.
- **CHAPTERS** list below. Each item is `mono-timestamp + sans-title`. The active chapter (the one currently being read) is highlighted via scroll-spy. The active timestamp picks up the accent color; the title becomes bold.
- The rail self-scrolls when the active chapter would otherwise be out of view inside the rail.

### Center column: prose

- Title block + italic lede (same `bottom_line` as the briefing's thesis).
- Chapter headings inline with the prose: `<h2><time>00:05:28</time> <span>AI pay packages</span></h2>` + italic summary line.
- Speaker labels in uppercase sans (`TIM FERRISS`, `ELAD GIL`) with the host getting the accent color, the guest getting muted ink.
- One paragraph per turn. No "Copy passage" buttons under each turn.
- Clicking a chapter timestamp copies a deep link to the clipboard.

### Search interaction

In-text marking using `<mark>` (yellow background, ink text). The original turn text is cached in `data-original-body` so cleared search restores cleanly. Implementation in `artifact.js`'s `wireSearch()`.

### Scroll-spy

`wireScrollSpy()` watches scroll position; on each rAF tick, finds the last `chapter-break` whose top is ≤ 140px from viewport top. That's the current chapter. The matching rail item gets `.active`. The rail scrolls the active item into view if it'd otherwise be out of bounds.

## Strict monotonic chapter anchoring

`build_chapters()` in `scripts/podcast_build.py` enforces that each chapter anchors to a turn AFTER the previous chapter's anchor. Two chapters cannot share `turn_id`, which would render the second chapter with no content under it. If chapter queries produce duplicate anchors, the cursor advances by one turn — but the right fix is more specific queries in `chapter_queries`.

## Do not regress to

These patterns have been explicitly removed and should not come back without a deliberate design conversation:

- **Topic Lenses** — chips that didn't actually filter anything.
- **Conversation Arc / Chapter Map** — SVG scatter plot of chapter dots over time. Tags-as-coordinates was decorative; on the briefing it duplicated the listening experience.
- **AT A GLANCE stat tiles** — 4 numbers (chapters / takeaways / claims / terms) that count the artifact, not the content.
- **Who's Talking speaker share** — bar chart of word counts per speaker. Recording metadata, not content.
- **OPEN CTAs card** — redundant with the topbar's folder tabs and the Read Next list.
- **Left-handle accent bars** — 3–4px vertical accent stripes on the left of cards or quotes. AI-design fingerprint.
- **Built-for callout card** — the field is preserved in `notes.json` but not currently rendered.
- **Per-turn "Copy passage" buttons** — visual noise; deep-link copy on the chapter timestamp covers the use case.

`scripts/podcast_build.py validate` greps for these strings in the rendered HTML and fails if any appear.

## Asset layout

- `assets/podcast-html/transcript-browser.html.tmpl` + `glance-dashboard.html.tmpl` — minimal HTML shells with `{{TITLE}}`, `{{CSS}}`, `{{APP_JS}}`, `{{DATA_JSON}}` placeholders. The asset names are historical — both are single-page renderers, not "dashboards."
- `artifact.css` — shared design system. Folder tabs, studio layout, rail, typography.
- `artifact.js` — `PodcastArtifacts.renderTranscriptBrowser()` and `PodcastArtifacts.renderGlanceDashboard()`. Both consume the embedded `#episode-data` JSON.

## Provenance

The HTML may summarize sources, but `metadata.sidecar.json` remains the audit trail. If a claim is source-backed, include a short evidence label in `claims[].evidence`. If a term has a canonical URL, put it in `verification.terminology[].url` — the inspector renders the term name as a link.
